# 下轮优化问题清单

这份清单记录下一轮有时间继续优化的功能问题。它不是长期愿景，而是从当前使用反馈里整理出来的可执行 Backlog，后续可以按优先级拆 Issue 或直接开发。

## 优先级说明

| 优先级 | 含义 |
|---|---|
| P0 | 会阻断主流程、导致任务失败、数据错乱或用户无法继续写作 |
| P1 | 严重影响生成质量、长篇稳定性或核心工作效率 |
| P2 | 体验明显不顺，但不阻断主流程 |
| P3 | 增强型能力，适合稳定后继续做 |

## P0 稳定性与数据一致性

### 1. 老数据体检与一键修复

现状：部分项目历史操作后可能残留重复章节号、重复任务、旧章节景观、旧质量记录。后续虽然修了部分查询崩溃问题，但旧数据仍需要可视化诊断和安全清理。

目标：

- 增加“项目数据体检”入口。
- 检测重复章节号、重复卷号、孤立质量记录、孤立景观事件、孤立任务。
- 提供只读报告和安全修复按钮。
- 所有修复前生成备份记录或至少输出待执行清单。

验收：

- 能列出同项目同卷同 `chapter_number` 的重复章节。
- 重新展开弧线后，旧景观线、质量仪表盘旧章节、旧事件可以按范围清理。
- 修复过程不删除用户正文，除非用户明确选择。

### 2. AI 任务去重与幂等

现状：部分生成任务曾出现双份，用户难以判断是否重复发布，结果也可能不一致。

目标：

- 为世界观、角色势力、大纲、弧线、章节展开、质量审计、按评审修复等任务生成稳定指纹。
- 同一项目、同一范围、同一参数的运行中任务不重复创建。
- 任务列表展示“复用已有任务 / 新建任务”的来源。

验收：

- 连续点击同一个生成按钮不会创建两个并发任务。
- 刷新页面不会重复发起后台任务。
- 任务详情能看到请求参数摘要和任务指纹。

### 3. JSON 输出修复与结构化容错

现状：AI 返回格式异常仍可能发生，尤其是展开弧线、质量审计、修复计划等长 JSON 输出。

目标：

- 所有 AI JSON 任务统一走 JSON 修复器。
- 前端错误详情展示“可读原因 + 原始片段折叠”，不要直接扔大段 JSON。
- 后端保留原始返回、修复后返回和失败原因。

验收：

- 返回数组/对象混乱、带 Markdown、字段缺失时能自动修复一轮。
- 修复失败时 UI 能看懂：缺哪个字段、哪个章节或哪个任务出错。

## P1 写作质量与长篇吸引力

### 4. 前 20 万字专项质量模型

现状：章节内容有时像深奥场景小说，缺少网文前期抓人感，前 20 万字留存不足。

目标：

- 创建“大前期吸引力审计”。
- 检查第 1 章、前 3 章、前 10 章、前 30 章、前 50 章。
- 输出主角立住、核心卖点、冲突启动、阶段兑现、追读钩子、通俗度评分。
- 支持按前期模型重拆卷纲、重拆弧线、重写章节蓝图。

验收：

- 能指出“为什么不吸引人”，不是只给分。
- 能生成前 20 万字强化建议，并能一键应用到大纲或弧线。
- 明确禁止合并章节这种不符合用户预期的建议。

### 5. 弧线重写与对话式调整

现状：卷轴下方缺少明确“重拆弧线 / 重写弧线 / 对话调整弧线”的入口，故事大概调整不够顺手。

目标：

- 每条弧线提供“对话调整”“重写弧线”“重新展开章节”“仅更新弧线摘要”按钮。
- 对话调整时能读取当前卷纲、弧线、章节、关键事件、用户新意见。
- 调整前提示会影响哪些数据：章节蓝图、景观线、质量记录、正文是否保留。

验收：

- 用户可以用自然语言说“太深奥，改通俗网文感”，系统能生成调整方案。
- 可以选择只改弧线描述，或连带重建章节蓝图。
- 已写正文默认不覆盖。

### 6. 批量写作完整继承写作设置

现状：单章写作有可读性、简单易懂、写作控制等设置，批量写作是否完整继承还需要系统化核查。

目标：

- 批量写作明确展示本次使用的写作设置。
- 支持可读性模式、标点风格、通俗度、章节长度、Skill、世界约束、生成限制。
- 批量写作前提供“设置预览”。

验收：

- 单章和批量写作使用同一套 `writing_controls`。
- 批量任务详情能看到每章实际使用的设置。

### 7. 标点与语言手感专项优化

现状：正文标点有时乱用，长句、破折号、引号、顿号和省略号不稳定。

目标：

- 增加“标点风格”设置：标准网文、口语轻快、严肃纪实、古风克制等。
- 质量审计增加标点问题定位。
- 局部修复支持只修标点和句读。

验收：

- 审计结果能指出具体句子里的标点问题。
- 修复后不改变剧情内容，只调整标点和句读。

## P1 质量审计与修复闭环

### 8. 单章审计后的修复按钮统一

现状：部分入口审计完后没有“重写 / 轻修 / 局部修复”按钮，AI 任务详情里也缺少后续动作。

目标：

- 质量仪表盘、工作台审计、AI 任务详情统一展示修复动作。
- 每个问题支持：只修原句、只修段落、深修此问题、整章轻修、按审计重写。
- 修复完成后问题状态改为“已修复 / 已忽略 / 待复审”。

验收：

- 从 AI 任务详情打开单章审计，也能直接发起修复。
- 修复后对应问题不再一直显示待处理。

### 9. 局部修复效果评估

现状：修复后分数可能只从 5 分到 6 分，用户难以判断修复意义。

目标：

- 修复前先生成修复目标和预期提升。
- 修复后自动复审同一问题。
- 如果提升低于阈值，提示“修复不足”，可继续重修。

验收：

- 每次修复显示：原问题、修改前片段、修改后片段、复审结论、分数变化。
- 支持“继续修到 8 分以上”。

### 10. 全量重写与局部修复边界

现状：用户希望“通知书毛边又长了一点”这种问题只改原句，而不是整章改写；但有些问题又需要段落或整章修。

目标：

- 修复策略先判断问题范围：句子、段落、场景、整章、跨章。
- 严格区分“局部替换”和“全章重写”。
- 局部修复必须用原文定位替换，不能让 AI 重新写整章后再找差异。

验收：

- 原句修复只替换一个可定位片段。
- 段落修复只替换包含问题的段落。
- 跨章问题必须提示需要更大范围，不静默乱改。

## P2 页面与交互

### 11. 景观图页面重构

现状：卷章景观泳道展示过多章节，滚动条明显，关系边太长时不好看。

目标：

- 卷章景观泳道改成折叠式分组、缩略泳道或时间轴视图。
- 关系边与因果连接支持短标签 + 点击展开详情。
- 提供按弧线、角色、事件类型筛选。

验收：

- 大卷 50 章以上不出现横向失控。
- 关系描述超过一定长度自动折叠。

### 12. 角色与势力页面统一中文类型

现状：角色类型、组织类型等出现英文，不符合中文创作语境，也限制类型表达。

目标：

- 类型字段全中文展示和输入。
- 类型不固定死，允许用户自定义。
- 旧英文值自动映射为中文显示，不破坏数据库。

验收：

- `protagonist / antagonist / faction` 等不直接出现在 UI。
- 用户可以输入“恋人”“吃瓜教父式反派”“隐线盟友”等自定义类型。

### 13. 大纲、记忆中枢、世界观页面排版继续优化

现状：部分页面字段太长时溢出或阅读密度不均。

目标：

- 大纲长弧线自动折行，支持展开全部。
- 记忆中枢增加按角色、伏笔、事件、风险筛选。
- 世界观页面修复长字段排版和层级视觉。

验收：

- 长文本不超出屏幕。
- 重要信息不被遮挡。

### 14. AI 任务详情可读化

现状：任务详情里某些评审弧线、修复计划仍直接显示 JSON，不适合普通用户阅读。

目标：

- 根据任务类型提供中文摘要视图。
- JSON 放到“原始数据”折叠面板。
- 错误、建议、修复计划、章节列表都用结构化中文展示。

验收：

- 用户不看 JSON 也能知道任务做了什么、失败在哪里、下一步怎么处理。

## P2 写作风格 Skill 后续增强

### 15. Skill 效果评分

现状：Skill 抽取后能使用，但缺少效果评估，不知道对生成质量是否真的有提升。

目标：

- 每个 Skill 记录被哪些项目引用。
- 章节审计时记录 Skill 贴合度。
- 支持对比“启用 Skill / 不启用 Skill”的章节质量差异。

验收：

- Skill 详情页显示平均风格贴合度、引用项目数、近期生成表现。

### 16. 多 Skill 混合

现状：一个项目当前只选择一个共享 Skill。

目标：

- 支持主 Skill + 辅助 Skill。
- 按阶段启用不同 Skill：开篇抓人、感情戏、战斗、世界观揭示、日常互动。
- 混合时明确权重和冲突处理。

验收：

- 创建项目时可选择多个 Skill。
- 章节写作时按章节功能自动选用对应 Skill。

### 17. Skill 二次精炼

现状：抽取后的 Skill 如果片面，需要重新上传样本整体再抽。

目标：

- 支持追加样本继续精炼同一个 Skill。
- 支持用户对 Skill 提意见，例如“人物情绪分析太浅”，然后让 AI 重构相关字段。
- 保留 Skill 版本历史。

验收：

- Skill 可以从 v1 升级到 v2。
- 项目可选择继续使用旧版或升级新版。

## P3 工程与开源增强

### 18. Prompt Registry 可视化

目标：

- 把当前硬编码 Prompt 逐步登记到 Prompt Registry。
- 支持版本、用途、输入变量、输出 Schema、测试样例。
- UI 中能查看和调整非危险提示词片段。

### 19. 数据库迁移体系

当前状态：

- 已有应用启动 migration，版本记录在 `schema_migrations`。
- 已有 Alembic 基础配置和首个 revision。
- 升级策略要求非破坏性：只追加结构或补索引，不自动重写用户小说内容。

后续目标：

- 增加 migration 单元测试和旧库升级回归测试。
- 增加升级前备份命令和 schema 检查命令。
- 补齐 PostgreSQL 下的完整升级验证。

### 20. Issue 模板与 Roadmap

目标：

- 增加 GitHub Issue templates。
- 增加公开 Roadmap。
- 把用户反馈分成 bug、quality、UX、prompt、docs、infra。

## 建议执行顺序

1. P0 老数据体检与一键修复。
2. P0 AI 任务去重与幂等。
3. P0 JSON 输出修复与结构化容错。
4. P1 前 20 万字专项质量模型。
5. P1 弧线重写与对话式调整。
6. P1 质量审计后的修复按钮统一。
7. P2 AI 任务详情可读化。
8. P2 景观图页面重构。
9. P2 Skill 效果评分和二次精炼。
10. P3 Prompt Registry 和数据库迁移工具化。
