# 写作风格 Skill

写作风格 Skill 是独立于项目的共享写作方法库。它不是某本书的私有字段，也不是“仿写某个作者”的开关；它用于从样本文本中抽象出可复用的叙事手法，并在不同项目之间复用。

## 核心原则

- Skill 内容存放在独立表 `writing_style_skills`。
- 项目只在 `Project.writing_style.active_style_skill_id` 中保存当前引用的 Skill ID。
- 同一个 Skill 可以给多个项目使用。
- 抽取结果只记录写作方法，不保存样本全文。
- 禁止复制原文句子、人物名、地名、专有设定和具体剧情。
- 生成时使用的是抽象规则，例如节奏、人物刻画、情绪推进、冲突组织和语言手感。
- 大文件抽取走后台任务，不让 HTTP 请求一直等待 AI 返回。

## 抽取维度

系统会从样本文本中抽取以下维度：

| 维度 | 说明 |
|---|---|
| 核心风格 | 整体阅读质感、叙事气质、类型味道 |
| 视角控制 | 第一人称/第三人称、贴近角色程度、信息遮蔽方式 |
| 节奏推进 | 开场速度、冲突密度、转场方式、章节收束节奏 |
| 章节结构 | 承接、目标、阻力、反转、钩子的组织方式 |
| 场景组织 | 场景如何进入、如何推进、如何退出 |
| 场景描写 | 感官锚点、动作细节、环境与剧情的结合方式 |
| 人物刻画 | 性格呈现、动机暴露、缺点与成长 |
| 角色声音 | 不同角色的表达习惯、口头逻辑、反应方式 |
| 对白 | 台词长度、潜台词、吐槽、冲突对白 |
| 情绪感情 | 情绪铺垫、爆发、回落和细腻感 |
| 人物关系 | 关系升温、试探、误解、信任建立 |
| 世界观揭示 | 设定如何通过事件、代价、选择自然暴露 |
| 信息控制 | 悬念、误导、伏笔、读者已知与角色未知 |
| 冲突设计 | 外部冲突、内心冲突、关系冲突、利益冲突 |
| 读者反馈 | 爽点、笑点、泪点、期待感、章末追读 |
| 细节风格 | 物品、动作、神态、生活质感的选择方式 |
| 语言手感 | 句长、段落、标点、比喻密度、通俗度 |
| 主题表达 | 价值观如何通过选择和后果体现 |
| 文笔工艺 | 句式、段落、停顿、标点、口语化程度、叙述粗粝度 |
| 段落推进 | 动作、反应、解释、对白之间如何切换 |
| 细节工艺 | 细节从哪里来，如何承载人物、情绪和后续伏笔 |
| 人物出场工艺 | 人物如何靠动作、称呼、反应、反差立住 |
| 情绪落点工艺 | 情绪如何落在物件、身体反应、沉默、打断和未说出口的话上 |
| 场景真实感 | 场景中的现实阻力、生活杂音、身体感受和具体后果 |
| 章节生产法 | 一章如何开场、铺垫、冲突、解释、给情绪落点和收尾钩子 |
| 可复用模式 | 可以迁移到原创项目的 8-12 个写作模式 |

抽取目标不是“读后总结”，而是“写法工艺拆解”。系统会要求 AI 分析作者实际如何写：

- 怎么进入章节，而不是只总结章节发生了什么。
- 怎么用动作、对话、反应和称呼立人物。
- 怎么选择生活细节、身体反应、物件和环境声音。
- 怎么把设定揉进争论、误会、行动和利益冲突。
- 怎么控制句子长短、段落节奏、停顿和标点。
- 怎么让情绪落地，而不是直接解释“他很难过/他很震撼”。
- 怎么在日常、铺垫、战斗、解释、情绪和结尾之间切换。

## 全流程使用

当前项目设定某个 Skill 后，后续 AI 工作流会读取该 Skill：

| 阶段 | 用法 |
|---|---|
| 创建小说 | 用 Skill 的创作指导约束题材展开、读者承诺和核心卖点 |
| 全书大纲 | 用 Skill 的结构规则控制长期节奏、冲突密度和主线爽点 |
| 卷弧线 | 用 Skill 的弧线推进方式拆分阶段目标、误判、反转和余波 |
| 章节蓝图 | 用 Skill 的场景、人物、信息控制方式安排章节事件 |
| 正文写作 | 用 Skill 的语言、对白、情绪、细节和钩子规则生成章节 |

## 样本上传与后台任务

写作风格 Skill 页面位于 Dashboard 的全局入口。它是共享资源页面，不放在某个项目详情页里。

上传流程：

```text
选择 txt/md 文本文件
  -> 前端只显示文件名和大小，不渲染全文
  -> POST /api/v1/writing-style-skills/analyze-upload
  -> 后端创建 writing_style_skill_extract 任务
  -> 前端立即返回，不等待 AI
  -> 页面“抽取任务”列表轮询任务状态
  -> 任务完成后 Skill 自动进入共享库
```

这样设计是因为小说样本可能有 10MB、20MB 甚至更大。前端不能把全文塞进 `TextArea`，否则浏览器会卡死；HTTP 请求也不能一直等待 AI 分析，否则会遇到 2 分钟超时。

任务接口：

| 方法 | 路径 | 说明 |
|---|---|---|
| `POST` | `/api/v1/writing-style-skills/analyze-upload` | 上传文本文件并创建后台抽取任务 |
| `GET` | `/api/v1/writing-style-skills/task/{task_id}` | 查看单个抽取任务 |
| `GET` | `/api/v1/writing-style-skills/tasks` | 查看当前用户的抽取任务列表 |

上传支持：

- `.txt`
- `.md`
- `.markdown`
- `.text`
- `.log`
- UTF-8 / UTF-8 BOM / GBK / GB18030 编码

当前单文件上限是 60MB。上传后端会读取文件内容，但不会保存样本全文。

## 推荐样本选择

长篇作品通常有 100 万到 200 万字，不建议一次性把全文塞给模型。更好的做法是分批选代表性片段：

- 开篇 2 到 5 章：抽取开场钩子、人物入场、读者承诺。
- 高潮章节：抽取冲突升级、反转、爽点和情绪爆发。
- 感情戏章节：抽取关系推进、细腻情绪、潜台词。
- 世界观揭示章节：抽取设定进入剧情的方式。
- 日常过渡章节：抽取节奏缓冲、生活细节、角色互动。
- 结尾或卷尾章节：抽取收束、余波、悬念交棒。

如果上传的是完整长篇文本，后端会做代表性采样：

- 优先识别章节标题。
- 按章节位置抽取开篇、前期、中段、后期、结尾附近样本。
- 如果识别不到章节标题，则按全文均匀切分多个窗口采样。
- 最终只把代表性样本送入 AI，避免直接塞完整百万字。

采样只能提高覆盖度，不能保证一次抽取理解所有写法。更稳妥的方式是按用途做多个 Skill：

- 开篇抓人 Skill。
- 感情戏 Skill。
- 战斗/冲突 Skill。
- 世界观揭示 Skill。
- 日常人物互动 Skill。

## 数据结构

`writing_style_skills` 主要字段：

| 字段 | 说明 |
|---|---|
| `user_id` | Skill 所属用户 |
| `name` | Skill 名称 |
| `description` | 简介 |
| `source_type` | 来源类型，当前默认 `sample` |
| `source_note` | 来源备注 |
| `sample_word_count` | 抽取时使用的样本字数 |
| `style_profile` | 完整抽取结果 |
| `prompt_fragment` | 可直接进入生成提示词的执行片段 |
| `is_public` | 是否公开，预留字段 |
| `is_active` | 是否有效，删除时软删除 |

`style_profile` 中的深度字段包括：

| 字段 | 说明 |
|---|---|
| `sample_diagnosis` | 样本覆盖度、置信度高的判断、还需要补充的样本 |
| `prose_craft_style` | 文笔工艺：句式、段落、停顿、标点、口语化 |
| `paragraph_flow_style` | 段落推进：动作、反应、解释、对白如何切换 |
| `detail_craft_style` | 细节工艺：细节来源、人物承载、情绪承载、后续复用 |
| `character_entrance_style` | 人物出场工艺 |
| `emotion_landing_style` | 情绪落点工艺 |
| `scene_reality_style` | 场景真实感工艺 |
| `chapter_production_recipe` | 开场、铺垫、冲突、解释、情绪、结尾六步生产法 |
| `reusable_patterns` | 可迁移写作模式 |

## API

| 方法 | 路径 | 说明 |
|---|---|---|
| `GET` | `/api/v1/writing-style-skills` | 获取当前用户的共享 Skill 列表 |
| `POST` | `/api/v1/writing-style-skills/analyze` | 从样本文本抽取并保存 Skill |
| `POST` | `/api/v1/writing-style-skills/analyze-upload` | 上传样本文件并创建后台抽取任务 |
| `GET` | `/api/v1/writing-style-skills/task/{task_id}` | 查询抽取任务 |
| `GET` | `/api/v1/writing-style-skills/tasks` | 查询抽取任务列表 |
| `PUT` | `/api/v1/writing-style-skills/{skill_id}` | 更新 Skill |
| `DELETE` | `/api/v1/writing-style-skills/{skill_id}` | 软删除 Skill |
| `PUT` | `/api/v1/projects/{project_id}/active-writing-style-skill` | 设置项目当前引用的 Skill |

## 合规边界

写作风格 Skill 的目标是学习抽象写作方法，不是复刻某部作品。Prompt 中会明确要求：

- 不使用样本文本原句。
- 不复制样本剧情结构。
- 不沿用样本人物、组织、地名、物品名和专有设定。
- 不输出“像某作者”的描述，而是转为可执行写作原则。
- 当前项目设定、角色、世界观和大纲优先级高于 Skill。
